# F5 Project summary

## Summary

`GET /api/v1/projects/{project_id}/summary` returns task totals for a project: total, count per status and overdue count. It must compute everything in one aggregate query, not by loading tasks.

## In scope

- Response data: `{total: int, by_status: {pending, in_progress, done, cancelled}, overdue: int}`. All four statuses are always present, zero when empty.
- Overdue means `due_date` is before today (UTC date) and status is pending or in_progress. A task due today is not overdue. Done and cancelled tasks are never overdue.
- One aggregate SQL query (`COUNT(*) FILTER (...)` or `GROUP BY`) after a project existence check. Unknown project returns 404 `PROJECT_NOT_FOUND`; malformed id returns 422 `VALIDATION_ERROR` with `field` `project_id`.
- Tasks of other projects are never counted.

## Out of scope

- Telemetry spans (F11). Per-priority breakdowns.
