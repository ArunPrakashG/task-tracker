# F6 Cursor pagination

## Summary

Adds cursor-based (keyset) pagination to `GET /api/v1/projects/{project_id}/tasks`. Pages stay consistent when tasks are inserted mid-walk, and ties on `created_at` are broken by `id`. No offsets.

## In scope

- Query params `limit` (default 20, 1 to 100) and `cursor` (opaque). Existing `status` and `priority` filters keep working and are preserved across pages.
- `app/core/pagination.py`: encode and decode an opaque url-safe cursor holding `(created_at, id)` of the last item.
- Keyset condition on the order `created_at desc, id desc`: `(created_at, id) < (cursor_created_at, cursor_id)`. Fetch `limit + 1` rows to compute `has_more`.
- Response `meta`: `{limit, has_more, next_cursor}`; `next_cursor` is null on the last page.
- A malformed or tampered cursor returns 422 `INVALID_CURSOR` with `field` `cursor`. `limit` outside 1..100 returns 422 `VALIDATION_ERROR` with `field` `limit`.

## Out of scope

- Pagination of projects. Total counts in meta.
