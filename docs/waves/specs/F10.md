# F10 Docker Compose and README

## Summary

One `docker compose up` runs the whole stack: the API, Postgres and Redis, with migrations applied on start. The README documents setup, the API, the response format and the migration rules.

## In scope

- `Dockerfile` using a Python 3.12 slim image and uv (`uv sync --frozen --no-dev`), running as a non-root user.
- `docker-compose.yml` with services `app`, `db` (postgres:16-alpine) and `redis` (redis:7-alpine). `db` and `redis` have healthchecks and `app` waits for them. `app` runs `alembic upgrade head` then `uvicorn app.main:app --host 0.0.0.0 --port 8000`. Host ports: app 8000, db 5433, redis 6380, so the stack never clashes with the developer containers `pg` (5432) and `redis` (6379). Credentials come from env with sane defaults, no secrets committed.
- `.dockerignore` and `.env.example` (documents `DATABASE_URL`, `REDIS_URL`, `RATE_LIMIT_REQUESTS`, `RATE_LIMIT_WINDOW_SECONDS` with local values).
- `README.md`: what the project is, run with Docker Compose, run locally with uv, environment variables, endpoint table for `/api/v1`, the response and error envelope with examples, the state machine diagram, the migration rules (never edit an existing migration, never alter the database directly), how to run tests and lint, and how background audit logging works.

## Out of scope

- Production hardening, CI configuration, deployment.
