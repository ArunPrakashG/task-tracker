# F4 Tasks API and state machine

## Summary

Create and list tasks inside a project, and move a task through its status state machine. The state machine is the key design decision: it lives in `task_service.py`, is a single declarative transition table, and is enforced under a row lock so concurrent requests cannot both win. A successful transition emits a `task.status_changed` event handled in the background, so the response never waits on side effects.

## In scope

- `POST /api/v1/projects/{project_id}/tasks` body `{title, priority?, due_date?}`: 201 with the task. `title` trimmed, 1 to 200 characters. `priority` defaults to `medium`. `due_date`, when given, must be strictly after today (UTC date); failure returns 422 `VALIDATION_ERROR` with `field` `due_date`. Unknown project returns 404 `PROJECT_NOT_FOUND`. Decorate with `@rate_limit()` and declare `request: Request`.
- `GET /api/v1/projects/{project_id}/tasks?status=&priority=`: 200, tasks of that project, optional filters that combine, ordered by `created_at` descending then `id` descending (this order is what F6 paginates). Invalid filter value returns 422 `VALIDATION_ERROR` with the filter name as `field`. Unknown project returns 404. List logic lives in `app/services/task_query.py`.
- `PATCH /api/v1/tasks/{task_id}/status` body `{status}`: 200 with the updated task. Allowed transitions only: pending to in_progress, in_progress to done, pending to cancelled, in_progress to cancelled. Everything else, including same-status and anything out of done or cancelled, returns 422 `INVALID_STATUS_TRANSITION` with `field` `status` and a detail naming the from status, the to status and the allowed targets. Unknown task returns 404 `TASK_NOT_FOUND`. An unknown status value returns 422 `VALIDATION_ERROR`.
- State machine: a `TRANSITIONS` dict in `app/services/task_service.py`. The transition loads the row with `SELECT ... FOR UPDATE`, validates, updates status and `updated_at`, commits.
- After a successful commit the route calls `emit(background_tasks, "task.status_changed", payload)` with payload `{task_id, project_id, from_status, to_status, changed_at}`. A rejected transition emits nothing.
- Task response shape: `{id, project_id, title, status, priority, due_date, created_at, updated_at}`.

## Out of scope

- Pagination (F6), audit logging handler (F7), real rate limiting (F8).
- Editing task title, priority or due date after creation. Fetching a single task.
