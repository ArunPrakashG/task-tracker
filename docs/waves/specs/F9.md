# F9 Test harness

## Summary

The shared foundation for the functional tests: a dedicated Postgres test database whose schema is built by running the real Alembic migrations (never `create_all`), an async HTTP client that runs the real app lifespan, data factories that insert rows directly, and per-test cleanup. All functional tests in the other features use these fixtures. Tests are functional only: they drive the HTTP API and check business behaviour, with no per-function unit tests.

## In scope

- `tests/conftest.py`:
  - Session fixture that creates the test database if missing (connecting to the `postgres` database). The name is `taskdb_<id>_test`, where `<id>` is the `TEST_DB_ID` env var or, by default, a short hash of the project directory path, so parallel git worktrees never share a test database. It points `DATABASE_URL` at it and runs `alembic upgrade head` in a subprocess. Redis is `redis://localhost:6379/15`.
  - Environment defaults for tests: `RATE_LIMIT_REQUESTS=1000` so unrelated tests are never throttled.
  - A guard function `assert_test_database(url)` that raises unless the database name ends in `_test`; it runs before any truncate.
  - Per-test cleanup that truncates every table except `alembic_version` (tables discovered from the database, so later features' tables are covered automatically) and flushes Redis database 15 (tolerating Redis being down).
  - `client` fixture: `httpx.AsyncClient` with `ASGITransport`, running the app lifespan, base URL `http://test`. Accept a per-test client address so rate limit tests can vary the client.
  - `db_session` fixture: an `AsyncSession` on the test database.
  - pytest-asyncio configured so fixtures and tests share one event loop (adjust `pyproject.toml` pytest settings if needed; F9 may edit that section only).
- `tests/factories.py` and fixtures `make_project(name=None, description=None)` and `make_task(project, title=None, status="pending", priority="medium", due_date=None, created_at=None)`. They insert via the session, bypassing API validation so tests can create past due dates, specific statuses and identical timestamps.

## Out of scope

- Any feature test beyond the harness checks. Mocking the database.
