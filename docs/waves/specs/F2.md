# F2 Data model and initial migration

## Summary

SQLAlchemy 2.0 models for `Project` and `Task`, Alembic wired for async Postgres, and the first migration generated with `--autogenerate` and reviewed by hand before commit. From this point the schema changes only through new migrations.

## In scope

- `app/models/base.py`: declarative `Base` with a naming convention (`ix_%(column_0_label)s`, `uq_%(table_name)s_%(column_0_name)s`, `ck_%(table_name)s_%(constraint_name)s`, `fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s`, `pk_%(table_name)s`).
- `app/models/enums.py`: `TaskStatus` (pending, in_progress, done, cancelled) and `TaskPriority` (low, medium, high) as `str` enums.
- `app/models/project.py`: table `projects`: `id` UUID PK (default `uuid4`), `name` unique not null, `description` nullable, `created_at` timestamptz default `now()`.
- `app/models/task.py`: table `tasks`: `id` UUID PK, `project_id` FK to `projects.id` with `ON DELETE CASCADE`, `title` not null, `status` default pending, `priority` default medium, `due_date` nullable date, `created_at` and `updated_at` timestamptz (server default `now()`, `updated_at` also refreshed on update). Status and priority are stored as VARCHAR with CHECK constraints (`native_enum=False`, `create_constraint=True`), not native Postgres enums, so enum changes are simple migrations. Indexes: `(project_id, status)` and `(project_id, created_at, id)`.
- `app/models/__init__.py`: imports every module in the package (via `pkgutil`) so `Base.metadata` is complete as later features add model files.
- Alembic: `alembic/env.py` async, reading `DATABASE_URL` from the environment or `.env` directly (no dependency on `app/config.py`), `target_metadata = Base.metadata`, `compare_type=True`. No URL in `alembic.ini`. Delete the placeholder `sqlalchemy.url`.
- The initial migration, generated with `uv run alembic revision --autogenerate -m "initial schema" --rev-id 0001`, producing `alembic/versions/0001_initial_schema.py`. Review it: constraints, indexes, server defaults and downgrade must all match the models.

## Out of scope

- Audit table (F7). Any query, route or schema.
