# F1 Foundation and common response

## Summary

The shared skeleton every other feature plugs into: settings, the async database engine and session dependency, the app factory with lifespan, automatic router and event-handler discovery, the common response envelope, structured error handling, a background event dispatcher, and no-op stubs for rate limiting and telemetry that later features replace. Features add files; they never edit `main.py` or `router.py`.

## In scope

- `app/config.py`: settings loaded from env and `.env` (`DATABASE_URL`, `REDIS_URL` default `redis://localhost:6379/0`, `RATE_LIMIT_REQUESTS` default 30, `RATE_LIMIT_WINDOW_SECONDS` default 60). Add `pydantic-settings` and `redis` dependencies.
- `app/database.py`: `engine`, `async_session_factory` (`expire_on_commit=False`), and a `get_db` dependency that yields an `AsyncSession` and rolls back on error. Services commit explicitly.
- `app/core/responses.py`: success envelope `{"success": true, "data": ..., "meta": null or object}`, helper `ok(data, meta=None)`, and a generic `Envelope[T]` model for `response_model`.
- `app/core/errors.py`: `AppError(status_code, code, detail, field=None)` plus handlers for `AppError`, `RequestValidationError`, `HTTPException` (including 404/405) and unhandled exceptions. Error body is `{"success": false, "error": {"detail": str, "code": str, "field": str}}`, with `field` omitted when not applicable. Validation errors use code `VALIDATION_ERROR` and `field` is the offending request field name (last element of the pydantic location). Unhandled errors return 500 `INTERNAL_ERROR` with no stack trace.
- `app/core/events.py`: `on(event_name)` decorator registering async handlers, and `emit(background_tasks, event_name, payload)` which schedules every handler through FastAPI `BackgroundTasks`. A handler exception is logged and never propagates.
- `app/core/rate_limit.py`: a no-op stub `rate_limit(limit=None, window_seconds=None)` decorator that preserves the wrapped function signature (use `functools.wraps`). F8 replaces the body.
- `app/core/telemetry.py`: no-op stub `setup_telemetry(app)`. F11 replaces the body.
- `app/main.py`: `create_app()` factory plus `app = create_app()`. Lifespan imports every module in `app/handlers/` and `app.models`, calls `setup_telemetry`, and disposes the engine on shutdown. Mounts `GET /health` returning the envelope with `{"status": "ok"}`.
- `app/api/v1/router.py`: `build_router(package)` auto-discovers every module in `app/api/v1/routes/` and includes its `router` attribute; `app/main.py` mounts the aggregate at `/api/v1`.
- `CLAUDE.md`: add architecture conventions: envelope and error format, error code list, router and handler auto-discovery, and the migration rule (see below).

## Out of scope

- Any domain model, schema, route or service (F2 to F8).
- Real rate limiting and real telemetry.

## Contracts other features rely on

- Error codes: `VALIDATION_ERROR` 422, `NOT_FOUND` 404, `PROJECT_NOT_FOUND` 404, `TASK_NOT_FOUND` 404, `PROJECT_NAME_CONFLICT` 409, `INVALID_STATUS_TRANSITION` 422, `INVALID_CURSOR` 422, `RATE_LIMITED` 429, `INTERNAL_ERROR` 500.
- Routes live in `app/api/v1/routes/<name>.py`, each exposing `router = APIRouter()`, with paths relative to `/api/v1`.
- Event handlers live in `app/handlers/<name>.py` and register with `@on("task.status_changed")`.
- Migration rule written into `CLAUDE.md`: never edit an existing migration and never change the database schema directly; every model change gets a new Alembic revision generated with `--autogenerate`.

## Steps

- F1.1 Add settings (`app/config.py`) and add `pydantic-settings` and `redis` dependencies with `uv add`.
- F1.2 Write `app/database.py` with the async engine, session factory and `get_db`.
- F1.3 Write the response envelope and the structured error handling modules.
- F1.4 Write the event dispatcher, the rate limit and telemetry stubs, and the router auto-discovery.
- F1.5 Write `create_app()` with lifespan and `/health`, update `CLAUDE.md`, and write the foundation functional tests.
